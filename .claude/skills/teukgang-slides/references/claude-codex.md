# Claude에서 Codex CLI spawn

사용자가 지정한 제작 방식: Claude는 생성형 이미지가 필요하면 **Codex CLI 프로세스를 spawn하여 이미지 제작을 위임**한다. Claude에 이미지 도구가 없다는 이유만으로 바로 사용자에게 그림을 요구하거나 작업을 중단하지 않는다.

1. `codex --version`, `codex exec --help`로 설치와 지원 옵션을 확인한다. 현재 프로젝트에서 실행하며 기존 인증·모델 설정을 이용한다.
2. 이미지별 장면, 표정, 흰 배경/검정 펜/통통한 캐릭터 기준, 참고 이미지 절대 경로, 출력 assets 경로를 작업 지시 파일에 적는다. Codex 담당 범위를 이미지 생성·저장·프롬프트 기록으로 제한한다. HTML/원고는 Claude가 수정하므로 덮어쓰지 않도록 명시한다.
3. 셸 프로세스로 `codex exec`를 spawn한다. `spawn`이라는 Codex 하위 명령을 만들어 쓰지 않는다. 예시(PowerShell):

```powershell
Get-Content -Raw -Encoding utf8 ./image-task.md | codex exec --cd . --skip-git-repo-check --sandbox workspace-write --output-last-message ./image-result.md -
```

4. 지시문에는 “사용 가능한 내장 이미지 생성 도구를 사용하고, 생성 결과를 지정 assets 경로에 복사하라. 이미지 생성 도구가 없거나 실행 실패하면 실패 이유를 정확히 보고하라. 실제 생성 대신 SVG/코드 그림을 만들거나 성공을 주장하지 말라. 임의로 유료 API 경로로 전환하지 말라”를 포함한다.
5. 종료를 기다리면서 독립적인 원고/레이아웃 작업을 진행한다. 종료 코드와 결과 파일을 확인하고, 실제 이미지가 존재하는지 확인한 뒤 직접 열어 화풍·표정·구도를 검수한다. 그림을 HTML에 내장하고 최종 화면을 검증한다. CLI 성공 종료만으로 이미지 성공을 판단하지 않는다.
6. Codex CLI에도 이미지 도구가 없거나 인증·실행 권한 문제가 있다면, 재시도 가능한 원인을 한 번 수정한 뒤 같은 문제가 지속되면 사용자에게 실제 제한을 알린다. CLI를 실행하면 반드시 이미지 도구가 생긴다고 가정하지 않는다. 권한·승인 우회 옵션은 추가하지 않는다.

이 위임은 이미지 제작 범위에 한정한다. 다른 작업이나 외부 게시·전송까지 자동 위임하는 권한으로 해석하지 않는다.
