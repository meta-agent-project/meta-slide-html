# 완료 검증

1. `python build.py`가 targetSeconds와 합계 일치를 확인한다. 페이지 번호·제목·발표자 노트가 최신 순서인지 본다.
2. Node에서 playwright를 사용할 수 있도록 프로젝트에 설치하거나 이미 제공된 의존성을 이용한다. `node validate.cjs`. Edge를 쓰려면 `BROWSER_CHANNEL=msedge`, 필요하면 `NODE_PATH`로 의존성 경로를 지정한다. Windows 경로를 소스에 하드코딩하지 않는다.
3. 검증기는 모든 장의 1280×720 스크린샷, 이미지 로딩, 경계 초과, runtime error, 모션 버튼 순서, 단계 이동/이전/재생/초기화, 단축키를 검사한다. 폰트와 이미지 로딩을 기다린다. 모션은 마지막 단계도 검사한다.
4. 자동 검사는 디자인 검토를 대체하지 않는다. 대표 정적 장, 밀도 높은 장, 모든 모션의 최종 장면을 직접 열어 한국어 줄바꿈·겹침·잘림·화살표 방향을 확인한다. 처음 화면만 보고 모션 정상이라고 하지 않는다.
5. 발표자 노트 열기, 문구 편집(제목/표), HTML 저장 후 재개방, JSON 내보내기/불러오기를 확인한다. 저장된 모션이 여전히 재생되는지 확인한다. 브라우저에 네트워크 요청이 필요한 폰트·이미지·JS가 남아 있으면 완전 오프라인이라고 부르지 않는다.
6. 전환만 있는 장에 불필요한 모션 버튼이 없는지, 최종 정리 뒤에 새로운 강의 내용이 나오지 않는지 검토한다.
7. 최종 전달은 파일 링크, 변경점, 실제 검증 결과, 남은 제약만 간결하게. 설명서만 만들고 강의 HTML이 완성됐다고 말하지 않는다.
